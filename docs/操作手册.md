## 一、项目概览

本项目是《API 设计与实现》课程大作业，实现一个简易版抖音 / 视频流推荐系统。

**固定架构：**

```
Android Frontend → RESTful API (HTTP/JSON) → Spring Boot API Server → gRPC Recommend Service → MySQL 8
```

**技术栈：**

| 项 | 技术 |
|---|---|
| 语言 | Java 17 |
| 后端框架 | Spring Boot 3.3.6 |
| 构建工具 | Maven（多模块聚合） |
| 数据库 | MySQL 8 |
| RPC | gRPC 1.65.1 |
| 视频存储 | 后端本地 `uploads/` 目录 |
| 前端 | Android (Kotlin + Jetpack Compose) |

### 2.3 已实现 REST API（7 个端点）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| `POST` | `/api/v1/auth/register` | 否 | 注册（BCrypt 哈希，返回 token） |
| `POST` | `/api/v1/auth/login` | 否 | 登录（返回 token） |
| `POST` | `/api/v1/auth/logout` | Bearer Token | 退出（服务端返回成功，客户端删 token） |
| `GET` | `/api/v1/me` | Bearer Token | 当前用户信息 + videoCount + likedCount |
| `POST` | `/api/v1/videos` | Bearer Token | 发布视频（multipart + JSON 双模式） |
| `GET` | `/api/v1/me/videos` | Bearer Token | 我的视频分页（cursor + limit） |
| `DELETE` | `/api/v1/videos/{videoId}` | Bearer Token | 删除我的视频（权限校验 + 软删除 + 幂等） |

### 2.4 统一基础设施（所有接口生效）

| 能力 | 说明 |
|---|---|
| 统一响应 | `{ code, message, data, requestId }` |
| 错误码 | HTTP + business code 双层（40001, 40101, 40301, 40401, 40901, 41301, 50001） |
| 全局异常处理 | BusinessException → API 错误响应 |
| 请求日志 | 记录 requestId、userId、method、path、query、请求体、响应体、耗时、状态码 |
| 敏感脱敏 | 密码、token 不写入日志；multipart 文件仅记录摘要 |
| Bearer Token 鉴权 | HMAC 签名 token，统一 Filter 校验 |

## 七、启动步骤

### 7.1 后端 — API Server（必需）

```bash
# 在仓库根目录执行

# 1. 先编译整个项目，确保没有编译错误
mvn -q compile

# 2. 启动 API Server（默认 http://localhost:8080）
mvn -pl backend/api-server spring-boot:run
```

**启动后表现：**
- 控制台输出 Spring Boot 启动日志，包括 `Tomcat started on port 8080`
- 可通过 `curl http://localhost:8080/api/v1/health`（待实现）或已实现接口验证
- 可访问 `http://localhost:8080/uploads/` 下的静态视频文件

### 7.2 后端 — gRPC Recommend Service（当前可跳过）

```bash
# 在仓库根目录执行
mvn -pl backend/recommend-service spring-boot:run
```

**当前状态：** Recommend Service 仅有 Spring Boot 启动骨架，无 gRPC 逻辑。启动后 gRPC 端口（9090）尚不能提供推荐服务，但可验证模块能正常启动。

当 T15-T16 完成后，该服务需先于推荐流 REST 接口启动。

### 7.3 运行测试

```bash
# 在仓库根目录执行，运行全部测试
mvn -q test

# 只运行 API Server 测试
mvn -pl backend/api-server -q test
```

**当前测试不依赖真实 MySQL**，可在无数据库环境下运行。

### 7.4 前端 — Android App（可选）

1. 用 Android Studio 打开 `frontend/` 目录
2. 等待 Gradle 同步完成
3. API Base URL 默认使用已部署后端 `http://47.95.238.140:18090/`，登录页不再暴露手动修改入口
4. 运行到模拟器或真机

**当前状态：** 前端已接入真实后端 API；发布页支持通过系统文件选择器上传本机视频，也保留内置素材作为备用选择，图片加载失败时使用本地占位资源。

## 八、API 快速验证

### 8.1 注册

```bash
curl -X POST http://localhost:8080/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"Pass1234!","nickname":"Test"}'
```

**期望响应（201）：**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user": { "id": 1, "username": "testuser", "nickname": "Test", "avatarUrl": null },
    "accessToken": "<token>",
    "expiresIn": 7200
  },
  "requestId": "req_20260610..."
}
```

### 8.2 登录

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"Pass1234!"}'
```

### 8.3 获取当前用户

```bash
curl http://localhost:8080/api/v1/me \
  -H "Authorization: Bearer <token>"
```

### 8.4 发布视频（multipart）

```bash
curl -X POST http://localhost:8080/api/v1/videos \
  -H "Authorization: Bearer <token>" \
  -F "caption=测试视频" \
  -F "videoFile=@/path/to/sample.mp4" \
  -F "durationMs=5000"
```

### 8.5 我的视频分页

```bash
curl "http://localhost:8080/api/v1/me/videos?limit=5" \
  -H "Authorization: Bearer <token>"
```

### 8.6 删除视频

```bash
curl -X DELETE http://localhost:8080/api/v1/videos/1 \
  -H "Authorization: Bearer <token>"
```

### 8.7 退出

```bash
curl -X POST http://localhost:8080/api/v1/auth/logout \
  -H "Authorization: Bearer <token>"
```

## 十、当前代码审查结论

### 10.1 架构合规性

| 要求 | 状态 | 说明 |

| Java 17 + Spring Boot + Maven | ✅ 合规 | 版本 3.3.6 |

| RESTful API | ✅ 部分合规 | 7/13 端点已实现，核心推荐未完成 |
| gRPC 推荐服务 | ❌ 未完成 | 无 proto 文件，无服务逻辑 |
| 本地 uploads/ 存储 | ✅ 合规 | multipart 上传可用 |
| 请求日志 | ✅ 合规 | requestId/userId/耗时/脱敏均覆盖 |
| Bearer Token 鉴权 | ✅ 合规 | HMAC 签名，统一 Filter |
| 不创建 auth_tokens | ✅ 合规 | 退出简化，客户端删 token |
| 不做预签名 URL | ✅ 合规 | 无 upload_objects 表 |

### 10.2 代码质量

- 包结构清晰：`auth` / `user` / `video` / `common` / `logging`
- 遵循分层架构：controller → service → repository → model
- DTO 与 model 分离良好
- 统一响应包装 `ApiResponse<T>`
- 使用 Spring Security Crypto（BCrypt）
- 测试覆盖 auth、user、video 模块

### 10.3 风险与问题

| 风险 | 严重程度 | 说明 |
