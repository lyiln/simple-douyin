## 5. 成员 B 的分工

### 5.1 gRPC 推荐契约（T15）
- 编写 `recommend.proto` 定义 `RecommendService.ListRecommendedVideos`，含 6 个 request 字段和 5 个 response 字段。
- 配置 Maven protobuf-maven-plugin（0.6.1）和 os-maven-plugin（1.7.1），生成 Java stub。
- 解决 Java 17 下 javax.annotation.Generated 缺失问题，补充 javax.annotation-api 依赖。

### 5.2 推荐规则实现（T16）
- 实现 CursorCodec：Base64 URL-safe 游标编解码（likeCount|createdAt|videoId）。
- 实现 RecommendRepository：派生表 SQL，内层 (SELECT COUNT(*) FROM video_likes) 子查询计算实时点赞数，外层 WHERE 和 ORDER BY 统一引用 t.like_count。
- 实现 RecommendServiceImpl：gRPC 服务端，参数校验（userId>0、limit 1-30）、游标分页（limit+1 判断 hasMore）。
- 修改 RecommendServiceApplication：实现 ApplicationRunner，在 9090 端口启动 gRPC Server。

### 5.3 推荐流 REST 端点（T17）
- 实现 RecommendGrpcClient：复用 ManagedChannel Bean，blockingStub 调用 gRPC。
- 实现 FeedService：校验 limit → gRPC 调用 → VideoRepository.findPostById → VideoPostAssembler.toResponse 按序组装。
- 实现 FeedController：GET /api/v1/feeds/recommended/videos，统一响应格式。
- 修改 BearerAuthenticationFilter：增加 FEED_PATH 常量，对推荐流接口强制 Bearer Token 鉴权。

### 5.4 推荐测试（T20）
- RecommendRepositoryTest：7 用例（R01-R07），@SpringBootTest + 真实 MySQL，验证排序、过滤、分页、游标。
- FeedControllerTest：10 用例，MockMvc + Mock，覆盖正常/401/400/500/日志/脱敏/R08 gRPC 调用验证。
- 经历两轮 Code Review（PR #3），修复 like_count 子查询和派生表别名引用问题，17 用例全部通过。

## 7. 协作方式

1. 后端与 Android/Web 客户端以 REST API 契约为联调边界。
2. API Server 与 Recommend Service 以 `recommend.proto` 为 RPC 契约。
3. 数据库结构以 `sql/schema.sql` 为初始化依据。
4. 文档描述与代码不一致时，以当前代码事实为准并及时更新文档。
5. 答辩前由团队共同检查两条核心演示场景、环境变量、数据库数据和服务器状态。
6. 服务器仅用于答辩演示，非演示时间可以关闭；团队不承诺长期生产运维。
