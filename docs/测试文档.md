# 测试文档

## 1. 测试目标

本文档面向《API 设计与实现》课程作业今晚提交版本，目标是验证以下交付闭环：

1. Android 主端通过 REST API 使用 Spring Boot API Server，推荐接口继续通过 gRPC 调用 Recommend Service。
2. 注册、登录、推荐、访问过滤、上下滑动、点赞、评论、发布、我的视频分页和删除权限满足课程要求。
3. MySQL 8、后端本地 `uploads/`、请求输入输出日志和接口耗时具备可验证证据。
4. 测试状态严格区分已有执行记录、仅有自动化代码、接口可测和仍需人工验收的场景，不把本次未运行的内容写成“已通过”。

## 2. 测试范围

本次覆盖：

- 账号：注册、登录、退出、`GET /me`、Bearer Token 鉴权。
- 推荐：REST 推荐入口、gRPC RPC 链路、点赞数排序、已访问过滤、游标分页。
- 视频互动：上下滑动、访问上报、点赞/取消点赞、评论列表、发表评论。
- 视频管理：multipart 发布、本地文件存储、我的视频分页、删除本人视频和越权控制。
- 数据与运维：MySQL 六张表、数据库写入和查询、统一响应、请求日志、敏感信息脱敏、耗时和健康检查。
- 客户端：Android 为主演示端，`web/` React 客户端为补充演示端。

不纳入主线验收：收藏、关注、分享、消息、搜索、对象存储、复杂推荐算法、独立 metrics、Nginx、CI/CD 和生产级 TLS。

## 4. 测试用例设计逻辑

1. 以两条课程演示流程为主线：推荐/滑动/点赞/评论，以及登录注册/发布/我的视频/删除。
2. 每个核心接口至少覆盖正常路径、非法参数、未登录路径和关键业务异常。
3. 点赞、访问和删除增加重复请求测试，验证幂等和计数一致性。
4. 推荐使用确定性数据验证 `实时点赞关系数 DESC, created_at DESC, id DESC`，并验证 `video_views` 排除规则。
5. 数据层同时检查写入结果、查询结果、唯一约束、软删除和游标分页。
6. 安全测试覆盖密码哈希、Bearer Token、当前用户绑定、删除归属校验、上传校验和日志脱敏。
7. 日志测试同时核对 requestId、输入、输出、HTTP/业务码、userId、错误和 `duration_ms`。
8. Android/Web 页面存在真实调用点不等于端到端通过；无自动化或本次未运行的页面流程保留人工验收状态。

状态口径：

- `已通过`：存在明确的历史运行记录，并能定位到对应测试类。
- `人工验收通过`：已有人工执行记录；本次未发现可引用记录，因此不使用该状态。
- `接口可测`：接口和测试代码已存在，但没有当前可复核执行产物。
- `部分通过`：已有局部自动化证据，但完整链路或全部验收点未验证。
- `未自动化`：主要依赖人工页面操作，未发现自动化测试。
- `待验证`：需要启动完整环境或执行端到端流程后确认。

## 10. 当前测试结论

1. 代码静态证据表明，课程要求的注册、登录、推荐、访问、点赞、评论、发布、我的视频、删除、日志、耗时、健康检查、MySQL schema、本地 uploads 和 gRPC 调用链均有实现入口。
2. 2026-06-18 已在 Java 17 + MySQL 8 环境运行 API Server 测试：16 个测试类、114 个用例全部通过（含成员 B FeedControllerTest 10 用例）。RecommendRepositoryTest（7 用例）和 VideoRepositoryTest（14 用例）因 @SpringBootTest 启动冲突本次未完成，两文件在 2026-06-10 开发环境中已验证通过。
3. 综合本次执行和 2026-06-10 历史记录，成员 B 推荐测试（FeedControllerTest 10 + RecommendRepositoryTest 7，共 17 用例）覆盖 R01-R08、E04、E10、P01、L01-L04，结果均为通过。
4. Android `VerticalPager`、真实网络调用和 Web 补充端均有代码证据，但没有前端自动化测试或本次端到端执行记录。两条课程演示流程目前结论为“待验证”。
5. 2026-06-18 API Server 测试 114 用例在本机 Java 17 + MySQL 8 环境通过。演示验收（Android/Web 端到端）仍需在答辩前人工回归。

## 11. 未覆盖风险

1. 本次已在 Java 17 + MySQL 8 环境运行 API Server 全部 MockMvc 测试（114 用例通过）；RecommendRepositoryTest 和 VideoRepositoryTest 因 @SpringBootTest 加载冲突未完成（2026-06-10 历史通过）。
2. README、旧测试计划和当前测试源码的测试数量不一致；答辩前必须以一次新的 Maven/Surefire 汇总统一口径。
3. 未执行 Android 真机/模拟器端到端测试，视频 URI、网络权限、演示服务器可用性和滑动播放体验仍可能影响现场演示。
4. 未执行 Web 端自动化测试；Web 目前只能作为代码存在且待人工回归的补充演示端。
5. 未验证 multipart 发布后的真实 HTTP 文件访问和 Android 播放，只验证了存储组件及静态映射代码/历史单测。
6. 未在完整环境中留下 REST → gRPC → Recommend Service → MySQL 的日志、截图或 trace 证据。
7. 请求日志已有局部测试，但尚未证明每个 REST 接口均完整记录输入、输出、业务码和耗时，也未生成实际平均/最大耗时统计。
8. `videos` 表保留 like/view/comment 兼容计数字段，而当前业务以关系表实时 `COUNT(*)` 为准；人工核对时必须以关系表和接口返回值为事实来源。
9. 本地 uploads 适合单机课程演示，未覆盖数据库写入失败后的孤儿文件清理、多实例共享、备份和容灾。
10. gRPC 当前为 plaintext，未覆盖 deadline、重试、TLS、服务发现和故障恢复；推荐服务不可用时仅验证预期错误处理代码，未做本次故障演练。
