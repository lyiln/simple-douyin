# Scope Final

## Context

本规划基于 `docs/gap-analysis.md`、`frontend/docs/API_DESIGN.md`、当前 Android Compose Demo 源码和课程大作业要求。当前仓库未发现 `AGENTS.md`，因此没有额外项目级 agent 规则可引用。

当前目标不是复刻完整抖音，而是交付“简易版抖音 / 视频流推荐系统”的课程必需闭环：账号 -> 发布视频 -> 推荐视频 -> 访问记录过滤 -> 点赞 -> 我的视频分页 -> 删除权限 -> 日志监控 -> 文档测试。

## P0 必须完成

| 模块 | 功能 | 验收口径 |
| --- | --- | --- |
| 用户系统 | 注册、登录、退出 | 注册后可登录；登录返回 token；退出后 token 不可继续访问需登录接口或客户端清除 token 有明确设计 |
| 鉴权 | Bearer Token 解析当前用户 | 未登录访问 P0 业务接口返回 401；无权限返回 403 |
| 推荐视频主页 | 推荐视频列表 | Android 端可上下滑动播放推荐视频；后端返回可分页推荐流 |
| 推荐规则 | 按点赞数最高推荐 | 推荐服务按 `like_count desc, created_at desc` 排序 |
| 浏览过滤 | 用户访问过的视频不再推荐 | 已写入 `video_views` 的视频不会再出现在该用户推荐流中 |
| RPC 推荐服务 | API Server 通过 RPC 调用 RecommendService | 客户端调 REST；REST 内部调 RPC 推荐服务，不直接在 Controller 拼推荐结果 |
| 点赞 | 点赞 / 取消点赞 | 幂等；重复点赞不重复加计数；取消点赞不重复减计数 |
| 发布视频 | 发布视频记录 | 登录用户可发布视频，视频归属当前用户 |
| 视频存储 | 视频与封面存储设计 | 至少支持本地文件存储或对象存储二选一，并在 README 写明配置 |
| 我的视频 | 分页查看我的视频 | `GET /me/videos` 支持分页，按发布时间倒序 |
| 删除我的视频 | 只能删除自己的视频 | 删除他人视频返回 403；删除后不再推荐、不再出现在我的视频 |
| 数据库 | MySQL 表设计 | 覆盖 users、videos、video_likes、video_views、request_logs，评论表可选 |
| 日志 | 记录输入、输出、耗时 | 每个用户请求记录 requestId、userId、接口、请求、响应、状态码、耗时 |
| 监控 | 健康检查和基础指标 | 至少有健康检查；接口耗时、错误数可从日志或 metrics 观察 |
| 安全 | 账号、密码、权限 | 密码哈希存储；删除/发布/点赞/浏览记录均绑定当前用户 |
| 测试 | 核心测试文档和用例 | 覆盖正常、异常、权限、推荐规则、日志 |
| 交付材料 | README、需求、技术设计、测试、PPT、分工、演示视频 | README 写部署步骤；其他材料按课程提交 |

## 最小演示闭环

1. 用户注册并登录。
2. 用户发布一个视频。
3. 我的页面分页看到该视频。
4. 当前用户删除自己的视频成功，删除他人视频失败。
5. 推荐页通过 API Server 调 RecommendService 返回未看过的视频。
6. 点赞某视频后，其 `like_count` 增加，推荐排序可体现点赞数影响。
7. 用户访问某视频后写入 `video_views`，再次刷新推荐流不再出现该视频。
8. 日志中可查到每个接口的输入、输出、耗时和 userId。
