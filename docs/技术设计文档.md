# 技术设计文档

## 1. 系统总体架构

本项目采用 Android 主客户端、React Web 补充客户端、REST API Server、gRPC 推荐服务和 MySQL 数据库组成的分层架构。视频文件由 API Server 保存到本地 `uploads/` 目录。

```text
Android 客户端 / Web 客户端
  -> REST API（HTTP/JSON 或 multipart/form-data）
  -> Spring Boot API Server
       -> Controller
       -> Service
       -> Repository（JdbcTemplate）
       -> MySQL 8

Android 客户端 / Web 客户端
  -> GET /api/v1/feeds/recommended/videos
  -> Spring Boot API Server / FeedController / FeedService
  -> gRPC / RecommendService.ListRecommendedVideos
  -> Recommend Service / RecommendRepository
  -> MySQL 8
  -> 返回 videoIds
  -> API Server 查询并组装视频详情
  -> Android 客户端 / Web 客户端
```

两个后端服务都可以访问 MySQL：API Server 负责账号、视频、互动、日志和 REST 协议；Recommend Service 负责推荐候选查询、访问过滤、排序和游标分页。Android 与 Web 均只通过 REST API 访问业务后端，不直接访问 MySQL 或 gRPC 服务。

## 3. 后端架构设计

### 3.1 Maven 模块

| 模块 | 职责 | 入口/依据 |
| --- | --- | --- |
| `backend/api-server` | 对 Android/Web 暴露 REST API，处理认证、视频、互动、日志、健康检查和推荐结果组装 | `ApiServerApplication.java` |

### 3.2 API Server 分层

| 层 | 职责 | 主要包 |
| --- | --- | --- |
| Controller | 定义 REST 路径、请求参数、媒体类型和 HTTP 状态码 | `auth/controller`、`video/controller`、`feed/controller` 等 |
| Service | 业务校验、当前用户获取、事务边界、业务流程编排 | `auth/service`、`video/service`、`comment/service` 等 |
| Repository | 使用 JdbcTemplate 执行 SQL，处理关系幂等、分页、软删除和聚合查询 | `auth/repository`、`video/repository`、`comment/repository` 等 |
| DTO/Model | 定义 API 请求响应和内部业务数据 | `**/dto`、`**/model` |
| Security/Token | 密码哈希、token 签发解析和 Bearer 路由鉴权 | `auth/security`、`auth/token` |

| Config/Storage | gRPC Channel 和本地上传配置 | `config/GrpcConfig.java`、`video/storage` |

### 3.3 统一响应与异常

REST API 使用统一外层：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "request-id"
}
```

`GlobalExceptionHandler` 将 `BusinessException` 映射为对应 HTTP 状态和业务码，将请求解析错误映射为 40001，将上传过大映射为 41301，将未处理异常映射为 50001。业务错误码定义于 `common/ErrorCode.java`。

## 4. Android 端架构设计

### 4.1 页面结构

Android 使用单 Activity + Jetpack Compose。`MainActivity` 初始化 `ApiClient` 并启动 `RealDouyinApp`，页面包括：

- 注册/登录页：`AuthScreen`。
- 首页推荐流：`HomeApiFeed` + `VerticalPager` + `VideoPlayer`。
- 发布页：`PublishApiScreen`。
- 个人页：`ProfileApiScreen`。
- 评论弹层：由主页面选择视频后加载评论并提交评论。

### 4.2 数据与网络结构

```text
Compose 页面
  -> RealDouyinApp 的 remember 状态与协程
  -> ApiRepository
  -> ApiService（Retrofit 接口）
  -> ApiClient（OkHttp、Bearer Header、SharedPreferences token）
  -> Spring Boot REST API
```

`ApiService.kt` 定义账号、用户、视频、点赞、访问、评论、推荐和健康检查接口；`ApiRepository.kt` 负责在 IO Dispatcher 中发起请求并将 HTTP/业务错误转换为 `Result`。`ApiClient.kt` 使用 SharedPreferences 保存 token，并通过 OkHttp Interceptor 自动添加 Bearer Header。

当前 UI 已调用注册、登录、退出、当前用户、推荐流、我的视频、访问上报、点赞/取消点赞、评论、multipart 发布和删除接口。`PublishAssetRepository` 仅负责把演示素材准备为可上传文件，发布结果仍来自后端。收藏、关注、消息、搜索等非主线页面已从当前主入口移除。

### 4.3 Android 端当前数据边界

| 功能 | UI 数据来源 | 网络层状态 | 当前说明 |
| --- | --- | --- | --- |
| 注册/登录/退出 | `AuthScreen`、本地 token 状态 | 对应 API 已调用 | 已接真实 API |

### 4.4 Web 补充客户端

`web/` 使用 React + TypeScript + Vite。`App.tsx` 管理登录态和推荐/发布/个人页切换；`api.ts` 统一处理 Bearer Token、统一响应和错误；`RecommendPage`、`UploadPage`、`ProfilePage`、`CommentDrawer` 分别覆盖推荐、上传、个人作品和评论。开发服务器默认监听 5173，并把 `/api`、`/uploads` 代理到 `VITE_PROXY_TARGET`。

## 5. 数据库设计

数据库初始化文件为 `sql/schema.sql`，字符集为 `utf8mb4`，存储引擎为 InnoDB。

| 表 | 主要字段 | 约束与索引 | 支撑功能 |
| --- | --- | --- | --- |
| `users` | `username`、`password_hash`、`nickname`、`status` | 用户名唯一 | 注册、登录、资料 |
| `videos` | `author_id`、媒体 URL、可见性、状态、三个计数兼容列、`deleted_at` | 作者时间索引、推荐候选索引、软删除索引 | 发布、我的视频、删除、推荐候选 |
| `video_likes` | `user_id`、`video_id`、`created_at` | `(user_id, video_id)` 唯一 | 点赞幂等、实时点赞数 |
| `video_views` | `user_id`、`video_id`、`source`、`watch_duration_ms` | `(user_id, video_id)` 唯一 | 访问幂等、推荐过滤 |
| `comments` | `video_id`、`author_id`、`content`、`deleted_at` | 视频时间索引、作者时间索引 | 评论列表、发表评论 |
| `request_logs` | requestId、用户、方法、路径、请求/响应、状态、耗时、错误 | requestId 唯一，用户/路径/时间索引 | 请求审计和耗时记录 |

schema 未定义物理外键。用户、视频及互动关系通过 ID 字段、唯一索引和 Service/Repository 查询校验维持。点赞数、访问数和评论数虽然在 `videos` 表中保留兼容字段，但当前代码从关系表实时 `COUNT(*)`；推荐排序也以 `video_likes` 的实时计数为依据。

当前数据库由单一 `schema.sql` 初始化，未确认存在 Flyway 或 Liquibase migration。

## 6. REST API 设计

接口统一前缀为 `/api/v1`。

| 方法 | 路径 | 鉴权 | 请求 | 响应数据 | 代码位置 |
| --- | --- | --- | --- | --- | --- |
| POST | `/auth/register` | 否 | username、password、nickname | user、accessToken、expiresIn | `AuthController.java` |
| POST | `/auth/login` | 否 | username、password | user、accessToken、expiresIn | `AuthController.java` |
| POST | `/auth/logout` | 是 | 无 | loggedOut | `AuthController.java` |
| GET | `/me` | 是 | 无 | profile | `UserController.java` |
| POST | `/videos` | 是 | multipart 或 JSON URL | video | `VideoController.java` |
| GET | `/me/videos` | 是 | cursor、limit | items、nextCursor、hasMore | `VideoController.java` |
| DELETE | `/videos/{videoId}` | 是 | path videoId | videoId、deleted | `VideoController.java` |
| PUT | `/videos/{videoId}/likes/me` | 是 | path videoId | liked、likeCount | `VideoController.java` |
| DELETE | `/videos/{videoId}/likes/me` | 是 | path videoId | liked、likeCount | `VideoController.java` |
| POST | `/videos/{videoId}/views/me` | 是 | source、watchDurationMs | viewed、viewCount | `VideoController.java` |
| GET | `/videos/{videoId}/comments` | 是 | cursor、limit | items、nextCursor、hasMore、commentCount | `CommentController.java` |
| POST | `/videos/{videoId}/comments` | 是 | content | comment、commentCount | `CommentController.java` |
| GET | `/feeds/recommended/videos` | 是 | cursor、limit | items、nextCursor、hasMore、strategy | `FeedController.java` |
| GET | `/health` | 否 | 无 | status、components | `HealthController.java` |

分页采用游标方式。视频和推荐默认 limit 为 10、最大 30；评论默认 20、最大 50。接口详细字段可以结合 `backend/api-server/src/main/java/**/dto` 和 `docs/api-contract-final.md` 阅读；若旧文档与 DTO 不一致，以当前 DTO 和 Controller 为准。

## 7. gRPC 推荐服务设计

### 7.1 RPC 契约

`backend/recommend-service/src/main/proto/recommend.proto` 定义：

```proto
service RecommendService {
    rpc ListRecommendedVideos(ListRecommendedVideosRequest)
        returns (ListRecommendedVideosResponse);
}
```

请求包含 requestId、userId、cursor、limit、是否排除已访问和策略名；响应包含 videoIds、nextCursor、hasMore、策略名和调试信息字段。

### 7.2 推荐调用链

```text
FeedController.recommendedVideos
  -> FeedService.listRecommended
  -> RecommendGrpcClient.listRecommended
  -> RecommendServiceImpl.listRecommendedVideos
  -> RecommendRepository.findRecommended
  -> MySQL
  -> gRPC 返回 videoIds
  -> VideoRepository.findPostById
  -> VideoPostAssembler
  -> RecommendedFeedResponse
```

### 7.3 推荐规则

推荐服务只选择：

- `status = published`；
- `visibility = public`；
- `deleted_at IS NULL`；
- 不存在当前用户的 `video_views` 记录。

排序规则：

```text
实时点赞关系数 DESC,
created_at DESC,
video_id DESC
```

游标同时保存点赞数、创建时间和视频 ID，以匹配排序字段并保证稳定翻页。该方案是满足课程要求的规则型简化推荐，不是复杂推荐算法或机器学习模型。

### 7.4 RPC 配置

API Server 使用单例 `ManagedChannel` 连接 `${RECOMMEND_GRPC_HOST:localhost}:${RECOMMEND_GRPC_PORT:9090}`，当前使用 plaintext。Recommend Service 在 9090 启动 gRPC Server，并使用 8081 作为 Spring Boot 管理 HTTP 端口。

## 8. 核心业务流程设计

### 8.1 注册与登录

```text
AuthController
  -> AuthService 校验输入
  -> UserRepository 查询/创建用户
  -> PasswordHasher 使用 BCrypt
  -> HmacTokenService 签发 token
  -> 返回统一响应
```

注册通过数据库唯一索引和 DuplicateKeyException 双重处理并发用户名冲突。登录时查询 `password_hash` 并执行 BCrypt 匹配。退出不维护服务端 token 黑名单，由客户端清除 token。

### 8.2 发布视频

```text
VideoController.publishMultipart
  -> BearerAuthenticationFilter 获取当前用户
  -> VideoService 校验标题、可见性和作者
  -> LocalUploadStorageService 校验并保存视频/封面
  -> VideoRepository 写入 videos
  -> 返回视频详情
```

### 8.3 点赞与访问

- 点赞：使用 `INSERT IGNORE ... SELECT FROM videos`，既保证关系幂等，也避免对不存在或已删除视频新增点赞。
- 取消点赞：按 userId + videoId 删除关系，重复取消不会产生额外副作用。
- 访问：使用 `INSERT ... ON DUPLICATE KEY UPDATE`；首次创建访问关系，重复请求更新来源、观看时长和更新时间。
- 计数：点赞数和访问数从关系表实时统计。

### 8.4 我的视频与删除权限

我的视频按当前用户 ID 查询，使用 `(created_at, id)` 游标倒序分页。删除前读取 `author_id`，只有当前用户是视频作者时才设置 `deleted_at`。视频已软删除时重复删除返回成功，删除他人视频返回 403。

### 8.5 评论

发表评论前校验 token、videoId 和内容长度。Repository 使用 `INSERT ... SELECT FROM videos`，确保目标视频存在且未软删除。评论列表按 `created_at DESC, id DESC` 分页，评论总数从未删除评论实时统计。

## 9. 视频存储设计

### 9.1 存储位置

| 类型 | 默认目录 | 默认大小上限 | MIME 类型 |
| --- | --- | ---: | --- |
| 视频 | `uploads/videos` | 100MB | `video/mp4` |
| 封面 | `uploads/covers` | 10MB | `image/jpeg`、`image/png`、`image/webp` |

`LocalUploadStorageService` 使用 UUID 生成文件名，不直接信任客户端原始路径；保存目标必须位于配置的 uploads 根目录内。`UploadWebMvcConfig` 将 `/uploads/**` 映射到本地 uploads 目录，使客户端能够通过 URL 访问媒体文件。

本地文件系统方案适用于课程项目和单机答辩演示，不承诺多实例共享、CDN、转码或长期容灾。

## 10. 日志与监控设计

### 10.1 请求日志

`RequestIdFilter` 为请求建立 requestId。`RequestLoggingFilter` 使用缓存包装器记录：

- requestId、userId；
- HTTP method、path、query；
- request body、response body；
- HTTP status、business code；
- durationMs；
- client IP、User-Agent；
- error message、createdAt。

multipart 文件内容不写入日志，只记录省略标记和长度。`SensitiveDataSanitizer` 对 password、token、authorization、secret 等字段脱敏。日志通过 `RequestLogRepository` 写入 `request_logs`；日志持久化失败只记录警告，不中断业务响应。

### 10.2 健康检查

`GET /api/v1/health` 检查：

- API Server：能执行到 Controller/Service 即标记 UP；
- MySQL：执行 `SELECT 1`；
- Recommend Service：检查 gRPC Channel 是否达到 READY。

所有组件正常时返回 200；MySQL 或推荐服务不可用时总体状态为 DOWN，并返回 503。当前没有独立 metrics 接口、告警平台或长期监控系统。

## 11. 认证与权限控制设计

| 控制点 | 实现方式 | 代码依据 |
| --- | --- | --- |
| 密码存储 | BCrypt 哈希 | `PasswordHasher.java` |
| token | HMAC-SHA256 签名，包含用户 ID 和过期时间 | `HmacTokenService.java` |
| REST 鉴权 | `BearerAuthenticationFilter` 对受保护路径校验 Header 和 token | `BearerAuthenticationFilter.java` |
| 当前用户 | 将解析后的 userId 写入 request attribute | `RequestContext.java` |
| 删除权限 | 比较视频 authorId 与 currentUserId | `VideoService.deleteMyVideo()` |
| 业务关系绑定 | 点赞、访问、评论和发布均使用当前用户 ID | 对应 Service/Repository |
| 日志脱敏 | JSON 字段和文本模式脱敏 | `SensitiveDataSanitizer.java` |
| 上传安全 | 大小、MIME、UUID 文件名和目录边界校验 | `LocalUploadStorageService.java` |

当前退出策略是客户端删除 token，服务端不维护 `auth_tokens`。当前未实现 refresh token、撤销列表、生产级密钥轮换、HTTPS 终止或接口限流。

## 13. 已知限制与风险

1. Android 与 Web 核心调用点已接入真实 API，但本次文档更新未启动服务或执行端到端回归，运行结果仍需以演示前验收为准。
